2. **Which refusal, and what is inside.** New `ProbePayload` (plain Java): on `not_a_message_database` it re-runs the container steps itself, using the reader's own package-private `BackupHeader`, `Gcm` and `BackupKey`. It verifies the tag before reading anything, and a failed tag discards the plaintext unread. It then names the branch: ZIP → `Sink.decide()`; inflated non-SQLite → `Sink.finish()`. It gives the payload's first 8 bytes in hex. For a ZIP it lists every entry: name with digit runs ≥6 masked, size, stored size, method, first 8 bytes, SQLite yes/no. Up to 4 SQLite entries are extracted and each gets the existing shape report (tables, `message`/`chat`/`jid` counts, columns, min/max time, overlap with the newest full backup, decrypted once). For inflated non-SQLite it gives the decompressed size, trailing bytes and first 16 bytes in hex. It also lists a ZIP found *inside* the inflated output, because that would otherwise cost another tap. Every file it writes starts `increment.` and is swept on return and at app start. The key file (`wa_key.bin`) and the event log (`live.jsonl`) do not match that prefix.
